# Auditoria — Liberty Begin (shell da aplicação, PWA, notificações, design system)

Nota inicial: `src/lib/navigation.ts` não contém definição de menu — exporta apenas `useGoBack`. Os menus por papel vivem em `src/components/AppLayout.tsx` (linhas 30–66 desktop, 84–104 mobile). A comparação "menu × rotas" abaixo usa esses arrays.

Inventário de `public/`: `apple-touch-icon.png` (180), `favicon.ico`, `icon-192.png`, `icon-512.png` (ambos `purpose: "any maskable"`), `firebase-messaging-sw.js` (único service worker — **não existe `sw.js`**), `manifest.webmanifest`, `placeholder.svg`, `robots.txt`, `images/`. Não há `vite-plugin-pwa`/workbox no `package.json`; o SW é manual e sem cache.

## PWA/Splash

- [SEVERIDADE: alto] `src/App.tsx:72-77` + `src/components/SplashScreen.tsx:21-24` — o Splash é renderizado **em vez** da árvore (`QueryClientProvider`, `AuthProvider`, `BrowserRouter` não montam) por 2,5s + 0,5s de fade = **3s por sessão** (`sessionStorage`, ou seja, toda abertura fria do PWA e toda nova aba). `getSession`/`fetchRoles`/queries só começam depois. — Impacto: TTI +3s em toda abertura; combinado com o `/` → Login → redirect, o usuário vê splash → login → dashboard. Para `/reset-password#access_token=…` o hash é consumido pelo `supabase-js` (importado estaticamente via `useAuth`, `detectSessionInUrl` default) **antes** do Splash acabar e o SDK limpa o hash da URL; `ResetPassword.tsx:19-40` então não encontra `access_token` e só funciona pelo fallback `getSession()` (linha 60). Funciona, mas por acidente. — Correção: montar a árvore inteira imediatamente e sobrepor o Splash como overlay (`AnimatePresence` sobre o app); reduzir para ~1,2s; pular splash quando `location.pathname !== "/"` (deep links) ou quando já há sessão em `localStorage`.
- [SEVERIDADE: alto] `src/components/UpdatePrompt.tsx:58-66, 91-97` — `hiddenSince.current` é setado ao esconder e **nunca zerado** ao voltar. Após o primeiro background >30s, qualquer `check()` futuro (timer de 30s ou `focus`) que detecte hash novo chama `reloadAppSafely()` **silenciosamente** mesmo com o usuário ativo digitando um relatório/formulário. — Impacto: perda de dados não salvos após deploy. — Correção: zerar `hiddenSince.current = null` no branch `visible`, e só auto-recarregar se a *transição* hidden→visible ocorreu agora e não há formulário sujo.
- [SEVERIDADE: médio] `src/components/UpdatePrompt.tsx:82-88, 139` — `schedule` fecha sobre `outdated` (sempre `false` no closure do `useEffect([])`), então o polling continua; e após o usuário "Dispensar" (`setOutdated(false)`), o próximo `check()` em 30s reabre o banner. — Correção: guardar `dismissedHash` em ref e parar o timer quando detectado.
- [SEVERIDADE: médio] `public/firebase-messaging-sw.js:57` — `fetch` no-op: nenhum precache/fallback offline. `manifest` promete `standalone`, mas abrir o PWA sem rede resulta em tela branca (nem `ErrorBoundary` sobe). Por outro lado, isso evita o problema de `index.html` antigo em cache — o `UpdatePrompt` faz `fetch(/index.html, no-store)` e funciona. — Correção: adicionar `vite-plugin-pwa` (Workbox `NetworkFirst` para navegação, `StaleWhileRevalidate` para assets com hash) e uma página offline; manter `skipWaiting`+`clients.claim` (linhas 59-60) para atualizações rápidas.
- [SEVERIDADE: médio] `src/components/PullToRefresh.tsx:19-68` — `useEffect` com deps `[pull]`: os quatro listeners são removidos/re-adicionados em **cada `touchmove`** (dezenas de vezes por gesto). Além disso, qualquer arrasto ≥80px com `scrollY <= 2` (inclusive dentro de um `Dialog`/`Sheet` ou carrossel) dispara `window.location.reload()` completo — não é "refresh de dados", é reload de app. — Correção: usar `useRef` para `pull`, ignorar quando o alvo está dentro de `[role=dialog]`/overflow scrollável, e trocar reload por `queryClient.invalidateQueries()`.
- [SEVERIDADE: baixo] `src/components/RefreshBubble.tsx:8-11` — `setSpinning(true)` e nunca `false`: se `reloadAppSafely` retornar `false` (cooldown de 15s em `appReload.ts:21-22` ou offline), o ícone gira para sempre. — Correção: `if (!await forceAppReload()) setSpinning(false)`.
- [SEVERIDADE: baixo] `src/lib/appReload.ts:4-16` — `clearAppCaches` apaga todos os `caches` exceto os com "firebase"/"messaging" — como o SW não cacheia nada, é no-op hoje; se adotar Workbox, isso apagará o precache a cada pull-to-refresh. Loops: `RELOAD_LOCK` 15s (`appReload.ts:2`) + `RELOAD_FLAG` 30s (`ErrorBoundary.tsx:49-52`) — proteção adequada, sem loop detectado.
